## `t3_thread_launch` result shape (scratch, with `modelSelection.options`)

Flat, not nested. Keys and value types only:

```json
{ "threadId": "string", "projectId": "string",
  "modelSelection": { "instanceId": "string", "model": "string", "options": "array(1)" },
  "runId": "string", "status": "string" }
```

`T3Mcp.launch` already reads the flat `{threadId}` form, so no fix to `mcp.ts` was needed. `options` is accepted and echoed back in `modelSelection`.

Other shapes seen: `t3_thread_wait` -> `{threadId, runId, status, timedOut}`, `t3_thread_organize` -> `{sequence}`.

## Version label

`VersionWatch` reports versions as `<serverVersion>+orch<orchestrationProtocolVersion>` (here `0.1.0+orch2`), so a protocol bump alone is a change and a repair branch name `repair/t3-<to>-<n>` stays one path segment.
