# Firmware Implementation Plan (plan 2 of 2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Cardputer ADV app. It speaks `docs/protocol.md` to the live relay and gives João the approved screens, approvals, replies, new tasks and voice, over any WiFi or hotspot.

**Architecture:**
- **Pure C++17 core** (`firmware/components/t3core`) holds every decision: protocol parsing and encoding, the app state machine, and the 40×11 character grid each screen draws into. It has no ESP-IDF includes, so it is unit-tested on the homelab host.
- **Thin device layer** (`firmware/main`) wires the core to the hardware: display, keyboard, mic, WiFi, NVS, and the wss client.
- **The agent tests on the real ADV over `/dev/ttyACM0`.** It flashes, reads logs, injects keys over serial and grabs framebuffer screenshots.
- **João is needed only at the four checkpoints** from the design.

**Tech Stack:**
- ESP-IDF v5.4.2 (user-local, `~/esp`)
- M5GFX ≥ 0.2.29 and M5Unified as IDF components
- `esp_websocket_client` with the esp-tls certificate bundle
- cJSON (IDF's `json` component on the device; a vendored copy for host tests)
- doctest for host tests, CMake + ctest
- esptool via `uvx`

**Spec:** `docs/superpowers/specs/2026-10-20-firmware-design.md`. It builds on `docs/superpowers/specs/2026-10-20-t3-cardputer-design.md` and the wire contract `docs/protocol.md`.

## Global Constraints

- **Wire contract:** `docs/protocol.md` is the contract. Where it's silent, match `relay/src/sim/device-sim.ts` and add the rule to the doc in the same task. Protocol stays v1: changes only add, never remove or rename, and never touch the "Never changes" section.
- **Nothing homelab-specific in the repo.** No relay URL, tailnet name, WiFi credentials or tokens. The relay URL comes from `firmware/local.cmake`, which is gitignored; the repo ships `firmware/local.cmake.example` with a placeholder. The CI leak grep must stay clean.
- **Token handling:** the device token is wiped only on close code 4401. On 4408, 1006 and any other close, reconnect with backoff and keep the token.
- **Receipts for every number.**
  - Every buffer, budget, timeout and interval is a named constant with a receipt comment citing a measurement on this ADV, or a `docs/receipts/2026-10-2x-<topic>.md`.
  - The `hello` values (`cols` 40, `bodyRows` 8, `maxFrameBytes`, `maxHomeRows`) come from those receipts.
  - Any limit hit shows on screen as `<budget>=<limit>, <what> needed <n>`.
- **Screen grid:** 40 columns × 11 rows.
  - Row 0 is the status bar, row 10 is the key-hint bar, and row 1 is the per-screen header where a screen has one. That leaves `bodyRows` = 8.
  - Screen layouts follow `docs/superpowers/specs/2026-10-20-t3-cardputer-screens.html`.
- **Memory:** one TLS connection, no PSRAM. All large buffers are allocated once at boot. The framebuffer is a 4-bit paletted sprite (240×135, about 16 KB).
- **Toolchain and access:**
  - Toolchain is ESP-IDF v5.4.2 only. No sudo: tools install under `~/esp` and `~/.espressif`.
  - The ADV is at `/dev/ttyACM0`, writable by the `plugdev` group.
- **Code style:** no code comments except receipts and external-constraint "why" lines.
- **Commits:** lowercase conventional commits with scope `firmware`, `relay`, `docs` or `ci`. No `Co-Authored-By` or agent credit.
- **Outward steps wait for João's go-ahead:** pushing, opening PRs, merging, and redeploying the live relay.

## Review Focus

1. **WiFi drops while the talk key is held.** The device stops recording, shows `voice: connection lost`, sends nothing stale on reconnect, and the next hold works. Pinned in Task 10.
2. **Relay restarts or the hotspot stalls during hello.** The device sees 1006 or 4408, reconnects with backoff, keeps its token, and Home comes back on its own. Pinned in Tasks 4 and 8.
3. **A request or question taller than the screen** (the relay leftover). The body scrolls, every option stays reachable, nothing is cut off silently. Pinned in Task 5.
4. **Hours of use with many reconnects.** Free internal heap and the largest free block stay stable, so TLS never starts failing from fragmentation. Pinned in Task 8 (soak).
5. **A full Home (more waiting threads than one screen).** The list scrolls, `needs` stays on top, and the section counts stay correct. Pinned in Task 5.
